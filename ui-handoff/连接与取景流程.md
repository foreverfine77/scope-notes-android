# 连接与取景流程（待审视觉方案）

用户已明确要求把连接设备与开始取景分开。当前 Android 0.18 尚未实现此拆分；本包新增的是可点击审核骨架。电量与预计分钟可以在已连接、尚未取景时显示。

建议保留底部固定的「选择设备」和「连接／取消／断开」两个位置。连接成功后，取景窗呈现盖板；盖板中用文字「开始取景」辅助新图标，避免首次使用猜测。圆形模式用圆盖板，微距用矩形。点开后开始视频，左侧边缘出现可点击的收起把手，位置随实际取景窗边界保持；不要求用户学会隐蔽的滑动手势。轻微掀开动画仅是待审视觉建议，减少动态时直接切换。

| 状态 | 取景窗 | 网络与电量 | 主要动作 |
| --- | --- | --- | --- |
| 未连接 | 连接引导 | 无有效读数用破折号 | 选择设备、连接 |
| 连接中 | 等待连接 | 不显示模拟读数 | 同槽取消 |
| 已连接未取景 | 盖板、开始取景 | 保留网络，查询电量，分钟标注「约」 | 点开盖板、同槽断开 |
| 正在取景 | 实时画面、边缘把手 | 保留网络，持续更新电量 | 拍照、录像、定格、收起 |
| 已定格 | 静止显示，可缩放检查 | 视频接收继续 | 恢复实时，或收起 |
| 录像或保存中 | 画面与状态反馈 | 沿用连接 | 禁用收起和其他会打断保存的操作 |
| 收起后 | 恢复盖板 | 停止视频，保留连接与电量 | 再次点开，保持原微距方向 |
| 意外断线 | 明确连接丢失 | 保留最后读数需标注过期，不能当实时读数 | 重连成功回盖板，由用户再打开 |

灯光需要实际验证。当前协议有视频 START/STOP 命令；电量查询线程却和视频接收会话绑在一起，原生实现要先拆开会话生命周期。STOP 是否熄灯、START 是否亮灯，以及仅查询电量会不会唤醒视频，都需要真机测试。盖板不能只盖住仍在工作的摄像头并声称已关灯。PWM 入口是否受本样机支持仍未确认。

定格是检查画面的显示功能；收起是停止视频的设备会话动作。不要使用相同图标，不把收起设计成播放／暂停。图库返回、屏幕旋转、后台恢复都应保持网络与取景意图明确；录制、保存、重连策略需要原生实现时专项回归。

本包演示入口：页面选 capture，状态选 connected-idle 或 macro-idle，再勾选「演示点击流」。图标仍是占位，Claude 需重绘。camera.start-preview 与 camera.stop-preview 是稳定动作 ID，不能改成连接／断开的别名。
